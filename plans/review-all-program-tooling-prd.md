## 1. Goal (G1 consumer + user-observable surface)

The consumer of every mechanism here is **the lead of the next `/review-all` Phase 6**, by the step of `skills/review-all/references/deliberation.md` it runs, and the sessions that lead spawns. Nothing is built for a consumer outside that protocol. When this PRD lands, a Phase 6 lead observes:

- **§Recording.** A ruling is one `record.py rule …` call; a reversal is `record.py rule --supersedes D<n> …`; the program doc's §Resolved decisions shows the newest ruling and names the one it superseded. No ruling lives only in a session transcript or a to-do file (reify: S6 R1–R8 and S24 R1–R5 did; S22 R1's reversal did).
- **§The program doc.** The doc is rendered by `program_doc.py` into the state home from `program.json`, the rulings, the ledger and the task store; `program_doc.py --publish` copies it and its `.state/` snapshot into the checkout immediately before the wave commit and prints the path list; the lead never edits it, and nothing else does either. A render whose `## ` headings would lose one the published doc has is refused (`--allow-drop <heading>` overrides, named) — the R1 F3 dropped-tail and R1 F12 stale-handoff incidents become impossible rather than unlikely. Re-rendering after the orchestrator moves tasks produces no diff: FILED carries no live status (R1 F13) and no read timestamp.
- **§Launching, author pass.** `gen_brief.py <S> author --spawn <title>` writes the brief at spawn time with the stream row after amendments, the rulings binding the stream, the finding statements and measurements in full with any `calibration_disputes_verdict` beside the verdict, the Phase 5 filings rows verbatim, the xrefs addressed to S, and prints the one spawn command: the brief's absolute path behind `--prompt-file`, `CLAUDE_SPAWN_SELF_EXIT=1` so the session ends itself. Every brief, both passes, carries the return schema and example, the absolute inbox path and the `apply_return.py --check` line; only a `--spawn` brief carries the spawn paragraph, and `--spawn` is accepted on the author pass only (`deliberation.md` §Launching: a spawned session runs the author pass; its decompose runs as an agent seat). A seat or session writes one JSON object to `inbox/<S>.<pass>.json` and runs `--check` on it before ending; the lead's `apply_return.py` validates it against `program.json` and the store, moves it to `returns/`, appends the ledger entries, and prints one digest line plus the `needs_human` questions. The lead reads the digest, never the JSON (`SKILL.md` §Lead context budget).
- **§Launching, the author-pass sitting (A7).** Every stream authors in agent mode; after critic → fold, `program_doc.py --sitting` renders the wave's pending design questions — the authors' `open_questions` and the critic blockers the fold seats re-emitted — as screens of at most four items in `deliberation.md` §How an item is put, each with its recommendation and the draft PRD's path, the `lead_rulable` ones as one uncontested yes/no block at the end; `record.py rule --answers S:Q…` closes an item, `--reask` returns it to a later screen after an investigating seat has probed, and the sitting ends when `--sitting` prints no pending item. An item the human escalates is briefed by `gen_brief.py <S> investigate --item Q --spawn <title>` for a self-terminating `/team` session whose return closes it. Measured basis: 8 of 47 spawned sessions carried design discussion; all 11 reify free-text overrides answered questions that already had a recommended option; spawn-to-pass-1 median 21.7 h.
- **§Launching, decompose pass.** `gen_brief.py <S> decompose` (an agent seat's brief; `--spawn` is refused here) carries the upstream filed ids and the release duties from the store, not from the lead's memory. `apply_return.py` rejects a decompose return whose filed ids are absent, carry a different `x_finding_run`, or claim a gate dependency the store does not hold — a transcription error is refused at the door instead of discovered at close-out (A's truncated held leaf; C's regex row drift). A form error is fixed in the inbox file and re-applied; a store contradiction stops for the lead; a lost return is reconstructed from the store with `apply_return.py --from-store <S>`, never re-filed.
- **§Launching, lead actions.** `clerk_batch.py write` turns every accepted, unapplied `action` into `actions/batch-<n>.json` plus the clerk prompt with the standing rules; the clerk seat applies them and `clerk_batch.py ingest` records each result. Nobody re-types a seat's prose into a batch file (scp: 17 batches, every action re-typed). `--scan` emits `repath` actions from each decompose return's `moves` for every non-terminal task whose delivered check anchors a moved path.
- **§Closing.** `gate_check.py` detects which trigger-chain form the store holds (`skills/_shared/filing-the-trigger-chain.md` §3 final or §4 interim), exits non-zero naming each missing or foreign dependency and each program task that would escape the completion measure, and the lead asks the human to `commit_planning` the gate only after it exits 0.
- **Spawned sessions.** `watch_sessions.py` resolves each spawned title to its registry record, copies `result.md` into `handbacks/` the first time it sees it, and reports a session as final only when its outcome is terminal **and** its record is `exited` (or carries `exit_requested_at` with a dead owner pid); `outcome: in-progress` is a checkpoint; a checkpoint whose record is already `exited` is reported "ended at checkpoint — relaunch or resume". A session spawned with `CLAUDE_SPAWN_SELF_EXIT=1` that has written its final `result.md`, run `/reflect`, and touched `exit-requested` ends itself within one turn; every other `/spawn` caller is unchanged (both Phase 2 siblings of two runs idled ~5 h).
- **Handoff.** A Phase 6 lead handing off mid-program runs `program_doc.py --handoff`, which writes `HANDOFF.md` from the state, the run record and the store; `--roster` prints one line per stream; the successor starts from those two outputs. The Phase 5 → 6 handoff stays hand-written from the report and record — no program state exists yet (`SKILL.md` §Lead handoff) — scp's resume cost 203k tokens of forensics.
- **G4 seeding.** `seam_scan.py <S>` lists, for the paths a stream's PRD touches, every non-terminal task outside the program that declares them in `metadata.files` or anchors them in `metadata.delivered_checks`, as candidate G4 rows (reify: the `codim` clash with #6669 surfaced after S9 had filed). It reads the store only: an authored-but-unfiled PRD is out of its reach, and the skill text says so.

Two rules bind every mechanism, stated once here and cited by the skill text: **the program doc is a render and the lead is its only editor**, and **nothing in this tooling commits** — every script that writes a committed file prints the `git commit --only` path list for the lead, who commits a wave once (`deliberation.md` §Commit cadence; after task 5411's docs fast lane lands, through the merge queue).

## 3. Sketch of approach

One library, six lead-run scripts, one fused-memory widening, three spawn-skill leaves, one skill-text leaf, one integration gate.

- **α `state.py`** — the single point of truth for the schema constants, the return validator, the state home and snapshot paths, append-only JSONL writes, and the one store reader over the MCP tool; with it the fixture program and the fake store every other leaf tests against. Every other script imports it and never queries on its own.
- **ρ** widens `find_tasks_by_metadata` with `include_rows=True`, echoed in the response, so the reader pages full rows under the existing byte budget and can tell a server that dropped the argument from one that honoured it.
- **β `apply_return.py` + `record.py`** — the only writers of `returns/`, `rulings.jsonl` and `ledger.jsonl`.
- **γ `program_doc.py`** — the only writer of the rendered doc, the `.state/` snapshot and `HANDOFF.md`, all into the home; `--publish` copies into the checkout; `--roster`.
- **δ `gen_brief.py`** — the only writer of `briefs/`; creates the `sessions.json` entries (η fills in the record); emits the spawn command.
- **ε `clerk_batch.py`** — the only writer of `actions/`; carries the `release` recipe and the `moves` impact scan.
- **ζ `gate_check.py` + `seam_scan.py`** — two store-derived checks: the gate's dependency set under either trigger-chain form, and the G4 seeding scan over `metadata.files` and `metadata.delivered_checks` (store only; no sidecar is read).
- **η `watch_sessions.py`** — resolves records, archives hand-backs on first sight, applies the inbox file once; final vs checkpoint per the D6 rule.
- **σ1, σ2, σ3** — the spawn skill: `--prompt-file` as a pointer prompt, `/reflect` and `in-progress` in the trailer, the outcome vocabulary moved to its one machine home, the `CLAUDE_SPAWN_SELF_EXIT` input; opt-in Stop-hook self-termination in its own module; the human-run tmux-lane probe.
- **κ** — the skill text cites the scripts and the machine homes where it now says "by hand until the program-tooling PRD lands" or restates a field list.
- **ω** — `scripts/check_review_all_program_fixture.py` walks a fixture program through every script, each as a subprocess under `python3 -I -S` from a cwd outside the repo, against the fake store; it is the PRD's signal.

**Import rule.** No script imports a third-party package. A script may import a first-party module that itself imports only the stdlib — `orchestrator.session_registry` and `sitting.ownership` both do, measured under `env -i /usr/bin/python3 -I -S` with a `sys.path` insert of `orchestrator/src` and `scripts` from the skill's checkout root (the `skills/spawn/hooks/stop.sh` pattern) — so the record shape, the terminal statuses and the outcome vocabulary are imported, never restated. The scripts live at `skills/review-all/scripts/program/`; their tests live at `tests/scripts/test_review_all_program_*.py`, because `tests/scripts/test_skills_module_config_decision.py::test_skills_has_no_tests_of_its_own` forbids a test under `skills/` (precedent: `tests/scripts/test_find_escalation_port.py`). Fixture data and the fake store server live beside the scripts under `skills/review-all/scripts/program/fixture/` (data and a server, not tests), so the lead can dry-run the loop without the test suite.

`wave` is never stored: it is 1 + the max of the upstream streams' waves (`state.py::waves`). FILED and held leaves have no file. The gate has no file. The program doc is a render. `measured_at` (when the store was read) is printed to the terminal and recorded in the ledger `commit` line, never in the doc body, so two renders over an unchanged program are byte-identical.

**State layout.** Working home `~/.claude/review-all/<run_id>/` (authoritative; overridable by `REVIEW_ALL_HOME` for the fixture walk; not `/tmp`, not the machine-operated checkout, not the `~/.claude/projects/<encoded-cwd>/` encoding). The rendered doc and its snapshot are written into the home and published into the checkout only immediately before the wave commit, so the machine-operated checkout is dirty for minutes, not for the hours a wave takes (one uncommitted file overlapping a queued branch halts every merge: `wip_conflict`, 1 h 48 m on 2026-09-21). Author-pass artefacts — each stream's PRD, manifest and sidecar through author → critic → fold — are written into the home under `prds/<S>/` and published into the checkout's `plans/` by `program_doc.py --publish` with the doc, immediately before the wave commit; the decompose pass runs only after that commit (`deliberation.md` §Launching: the PRDs go into the wave's one commit, then decompose), so the only artefacts dirty in the checkout for longer than the publish-to-commit minutes are the sidecars `commit_planning` re-stamps at decompose and a `release`/`repath` edits — `commit_planning` locates a sidecar from `metadata.prd_path` under `project_root`, so those cannot live elsewhere. That window is bounded by the wave: it opens at the first decompose of a wave and closes at that wave's commit; `release`, `repath` and the decompose seat return every sidecar path they dirtied so the lead's commit list is complete, and the lead commits a wave as soon as its last decompose returns rather than waiting on anything else.

```
<plans_dir>/review-all-program-<project_id>-<YYYYMMDD>.md     published by program_doc.py --publish; never hand-edited
<plans_dir>/review-all-program-<project_id>-<YYYYMMDD>.state/
    program.json  rulings.jsonl  ledger.jsonl                   copies of the home's three files at the last publish
~/.claude/review-all/<run_id>/
    program.json  rulings.jsonl  ledger.jsonl                   the home (record.py writes; program_doc.py reads)
    render/<doc name>.md, render/.state/                        program_doc.py's output; --publish copies from here
    prds/<S>/<slug>-prd.md, …capability-manifest.{md,yaml}      author-pass artefacts; --publish copies them into plans/
    inbox/<S>.<pass>.json         a seat or session writes its return here, its own file only
    returns/<S>.<pass>.json       apply_return.py moves the inbox file here; never overwritten
    handbacks/<S>.<pass>[.checkpoint-<n>].md   result.md copied on first sight by watch_sessions.py
    briefs/<S>.<pass>.md          gen_brief.py output, written at spawn time
    actions/batch-<n>.json, batch-<n>.prompt.md, batch-<n>.result.json
    sessions.json                 {title: {stream, pass, spawned_after, record_dir|null}}; δ creates, η fills record_dir
    HANDOFF.md                    rendered by program_doc.py --handoff
```

`program.json` carries `doc_path`; `program_doc.py` derives nothing from the run date at render time, so the doc's name never drifts from the record's (the four runs so far used four spellings). Resume reads the home; when the home is absent it reads the snapshot and the store and says so (`SKILL.md` §Lead handoff).

**`program.json`** (`schema: "review-all-program/1"`): `run_id, project_id, project_root, as_of_sha, record_path, doc_path, plans_dir, streams[{id, name, slug, remedy, deletable, keys[], mode: agent|spawn, size: S|M|L, risk: low|medium|high, deps[], seams[]}], seams_extra[{seam, owner, consumers}], invariants[{n, statement, owner, inv_id|null}], routed[{key, route}], conventions_extra[], triage[]`. `record.py init` validates it (a key in two streams, a dep naming no stream, a dep cycle, an unknown mode/size/risk are rejected, named) and refuses to overwrite an existing file.

**`rulings.jsonl`** line: `{id: "D<n>"|"L<n>", ruled_by: human|lead|"lead (--yes)", date, stream|null, item, question, ruling, options[], consequence, keys[], source, supersedes|null}`. `options` and `consequence` are required when `ruled_by == human`. A ruling made in the author-pass sitting carries `answers: ["<S>:<question id>", …]`, which closes those items, and `reask: true` when the answer was free text that an investigating seat must probe — the item stays pending for a later screen until a ruling without `reask` names it. Ids are minted by `record.py` and `apply_return.py` in one `D<n>`/`L<n>` namespace; a session-local id in `rulings_in_session` is re-minted on apply and the original kept in `source`.

**`ledger.jsonl`** line: `{seq, at, by, op, …}` with `op` one of `stream_status` (`stream, status ∈ briefed|spawned|authored|committed|decomposed|recorded, prd_path?, return?`), `amend_stream` (`stream, field ∈ keys|deps|deletable|mode|remedy, change ∈ add|remove|set, value, ruling`), `amend_program` (`section ∈ seams_extra|invariants|routed|conventions_extra|triage, value, ruling?`), `xref` (`from, to, text, return`), `action` (`id, op, task, target, text, needs_human, return`), `action_result` (`id, state ∈ applied|skipped|rejected|kept-for-human, batch, detail`), `scanned` (`return, repaths`), `note` (`text`), `commit` (`sha, paths[], measured_at`). `seq` is dense and ascending; `state.py::append` takes an advisory `fcntl.flock` on the JSONL file for the write (two appliers exist: the lead's `apply_return.py` and η), refuses a line whose `seq` is not the next one and never rewrites a line. `apply_return.py` is all-or-nothing: it validates the whole return and computes every line first, then appends them under one lock, so a rejection leaves nothing behind.

### Return block (contract H2)

Schema `review-all-prd-return/1`: one JSON object written by every `/prd` seat and spawned session, agent and spawn modes alike, to `~/.claude/review-all/<run_id>/inbox/<S>.<pass>.json`, and nowhere else — a spawned session's `result.md` names that path in its prose and carries no copy (one channel, so nothing is applied twice). An agent seat's final message is one line — `<S> <pass>: <n> filed, <h> held, <q> questions, <a> actions → inbox/<S>.<pass>.json` — so the lead reads digests, never return JSON. `state.py::RETURN_SCHEMA` and `state.py::validate_return` are the machine home of this contract; this section states it at design time; `deliberation.md` §Launching cites the symbols and restates no field list.

**Both passes** (`*` required):
- `schema*`, `run_id*`, `stream*`, `pass*` ∈ `author|decompose|investigate`, `session*` `{kind: agent|spawn, title}`. An `investigate` return (the escalated `/team` session of A7 §5, written to `inbox/<S>.investigate-<question id>.json`) carries `rulings_in_session` and `notes` only; its rulings close the item.
- `prd_path*`, `manifest_path`, `sidecar_path`.
- `commits`: always `[]` — seats and sessions never commit; a non-empty list is rejected.
- `open_questions` `[{id, question, options[], recommendation, needs_human, lead_rulable, source}]`; `needs_human` is true for a question that reverses a ruling, cancels a live branch or moves a board figure; `lead_rulable` (default false) marks naming, file-placement and seam-id questions the lead may rule — they are still shown to the human as one uncontested block (A7 §3); `source` ∈ `author|critic` (a fold seat re-emits the return with `--amend`, adding the critic blockers that need a ruling as `source: critic`). Every design-level question goes to the sitting; none is answered in a seat.
- `rulings_in_session` `[{id, question, ruling, options[], consequence}]` — rulings the human made inside a spawned session; appended to `rulings.jsonl` with `ruled_by: human` under a re-minted id.
- `seam_dependencies` `[{stream, contract}]`.
- `xrefs` `[{to, text}]`, `to` a stream id, `"program"` or a task id. Never a FILED row.
- `lead_actions` `[{op, task, target, text, needs_human}]`, `op` ∈ `cancel|edge|note|stamp|repath|release|amend` with the effects in H4.
- `notes`: at most 600 characters.

**Author pass only:**
- `touches*` `[path]`: every repo-relative path the PRD's decomposition plan names. `seam_scan.py` reads it (G4 seeding, §1).

**Decompose pass only:**
- `filed*` `[{label, task_id, priority, keys[], gate_dep: bool, adopted: bool}]`.
- `held` `[{label, task_id, waits_on, contract, release_owner}]`.
- `released` `[{task_id, onto[], contract_as_delivered}]` — other streams' held leaves this session released.
- `commit_planning` `{committed[], excluded[], stamping_errors[]}`.
- `other_filed` `[{task_id, why}]` — follow-up defects filed outside the PRD.
- `moves*` `[{from: path, to: path|null, symbols: [str]}]`: every path or symbol the stream's leaves move, rename or delete (`to: null` is a deletion). `clerk_batch.py --scan` reads it; `[]` is a valid, explicit answer.

Dependencies are absent from the return by design: the store holds them.

**Validation** (`apply_return.py`, through `state.py::validate_return`) rejects the return and writes nothing, naming the field and the class of the rejection:
- **Form** (fix the inbox file and re-apply): unknown `schema`, `pass`, `op` or extra top-level key — a decompose-only key on an author return, or `touches` on a decompose return, is an extra key, even when empty; `run_id` not the home's; `stream` not in `program.json`; `held.waits_on` not a stream id; a `moves` entry whose `from` is not repo-relative; `commits` non-empty; `notes` over the cap; a file that does not parse.
- **Contradiction with the store** (stop for the lead): a decompose return before the author return was applied; a `keys` entry outside the stream's keys after amendments; a filed id absent from the store; a store row whose `x_finding_run` differs, or whose `prd_path` differs while `adopted` is false; a held id not `deferred` or lacking `x_seam_wait`, or whose `x_seam_wait.stream` differs from the return's `waits_on`; a `gate_dep: true` that is not a dependency of the gate; a `released` entry whose target does not carry `x_seam_released` or whose dependency is not in the store.

`apply_return.py --check <file>` runs the same validation and writes nothing; the brief tells every seat and session to run it before ending. `apply_return.py` is idempotent on filed ids: an `<S>.<pass>` already in `returns/` is refused unless the content hash differs, and then only with `--amend`, which appends the delta as new ledger entries and keeps the first file. `apply_return.py --from-store <S>` reconstructs `filed`, `held` and `released` from the store for a session that ended without a usable return (a usage-cap kill; A's five, C's S26) — the open questions, xrefs and actions of that return are lost and the ledger says so; nothing is ever re-filed from a transcript. Degeneracy is judged on the inbox file (absent, unparsable, or under 100 bytes), never on the length of a seat's digest line.

### H3 — the store reader

`state.py::StoreReader(server_url, project_root)` is the only code that reads the task store. It speaks MCP JSON-RPC over `urllib.request` (`initialize` → `notifications/initialized` → `tools/call`, the `mcp-session-id` header, `Accept: application/json, text/event-stream`, the first `data:` line of an SSE body) — the wire shape of `scripts/migrate_metadata_modules_to_files.py::FusedMemoryClient`, re-stated in stdlib because every existing client needs `httpx` (resolved decision 3). It never opens sqlite: reify's `CLAUDE.md` forbids direct reads while fused-memory is up, and its run recorded that constraint.

- `program_tasks() -> list[TaskRow]`: pages `find_tasks_by_metadata(key="x_finding_run", value=run_id, include_rows=True)` on `has_more`, then for each stream `prd_path` in the ledger pages `find_tasks_by_metadata(key="prd_path", value=<path>, include_rows=True)`, unions by id. A `TaskRow` is `{task_id, title, status, priority, updated_at, metadata, dependencies}`.

- Every reader result carries `measured_at` (UTC); it is printed and ledgered, never rendered into the doc (H1).
- **Home (heuristic 14; task 7325).** The reader stays in `state.py`: β–η bind to `state.StoreReader`, `state.open_reader` and `state.StoreRead` under decision 17, so moving it while a leaf is open breaks that leaf. ## 5. Resolved design decisions

1. **The doc is a render; one editor; nothing commits.** Only the lead runs the scripts that write the home and render the doc; seats and sessions write only their own return file and PRD. The lead commits a wave once with `git commit --only` on the printed path list, until task 5411 lands; the snapshot rides in that commit, so the tooling adds no commits. (Leo A1 (c)+(d), B4; S3 G1/G2 closed.)
2. **Store reads over MCP; the tool is widened and echoes** (Leo A1 (b); D8 B1). `include_rows` rather than a sibling tool: the lookup PRD's row shape was chosen for the envelope bound, which the existing budget fitter already enforces per page, and a second tool would duplicate the key grammar, the statuses filter and the paging. `metadata` and `dependencies` are the two fields a render needs; `description` is not returned (a `release` rewrites it through `update_task`, which needs no read). The echo is what lets a stdlib client distinguish a server that honoured the argument from one that dropped it; task 6581's `get_tasks(fields=…)` projection is the sibling tool's answer to the same need and is not duplicated here.
3. **Stdlib reader, not `FusedMemoryClient`.** The lead runs these scripts from `~/.claude/review-all/<run_id>/` with the host's `python3`; `/usr/bin/python3` here has no `httpx`. This is the first stdlib copy of the handshake beside at least seven `httpx` ones (INV-5); it is bounded to one class in one file, its test asserts the same envelope `FusedMemoryClient._initialize` sends, and open question 1 names `shared/src/shared/mcp_post.py` as its eventual home.
4. **FILED carries no live status and no read timestamp** — program-level states only (`filed`, `held`, `released`, `cancelled-as-accepted`), so a render after the orchestrator moves tasks produces no diff (R1 F13). Live status is read from the store by whoever needs it.
5. **Rulings are append-only; a reversal is a new line with `supersedes`** (A's R15 reworded in place; C's S22 R1 reversal in a to-do file). The renderer shows the newest and names the superseded id.
6. **No file for FILED, held leaves or the gate**; the returns are audit, never a render source. The held-leaf keys stay `x_seam_wait` / `x_seam_released` in the `x_` namespace (Leo G4: no blessing). Their machine home is `state.py::SEAM_WAIT_KEYS` / `SEAM_RELEASED_KEYS`; `report-format.md` §Artefact 3 describes them for humans and (after κ) cites those symbols instead of restating a field list.
7. **The clerk seat writes; scripts never write the store or the sidecars.** `clerk_batch.py` produces the batch and ingests the result; the writes go through fused-memory MCP from a seat, so the TaskInterceptor's events fire and the seat's `get_task`-first rule holds. The sidecar yaml and md twin are edited by the seat too — no script here needs a YAML writer (stdlib has none) or a prose parser (heuristic 12) — and every dirtied path is returned for the wave commit.
8. **`moves` and `touches` are required fields with `[]` allowed**, so a seat that moved nothing says so and the scan can record "scanned, nothing" rather than "not scanned".
