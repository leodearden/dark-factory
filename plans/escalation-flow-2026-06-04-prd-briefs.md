# Escalation-flow PRD briefs + seam ownership register (2026-06-04)

Origin: a 16-agent verified audit (7 deep-dives, adversarial re-trace of every high/critical
finding) of escalation-watcher, escalation-watcher-auto, the escalation queue/server, and the
harness re-pend logic. Goal frame for all three PRDs: **increase throughput by reducing latency
of issue handling and task scheduling, without sacrificing final correctness of code reaching
main.** Every file:line below was verified against the working tree on 2026-06-04.

Three PRDs run as **concurrent** sessions. They are disjoint by construction: the one genuinely
coupled pair (escalation gates/terminate semantics and flip durability — same state machine) is
folded into a single PRD (Brief 3), and the three shared artifacts have section ownership
pre-assigned below.

## Brief 1 — PRD: escalation watcher & queue operations hardening (PRD-1)

Issues (priority order):

1. **L1 rotation never completes — force-killed every cycle (live, 10/10 in journal).**
   SKILL.md mandates one foreground-blocking `python -m escalation.watcher --level 1` wait for
   the whole rotation (escalation-watcher-auto/SKILL.md:221-230), but rotations run as
   `claude --print` whose Bash tool caps at 10 min; no `BASH_MAX_TIMEOUT_MS` override is injected
   (cli_invoke.py:823-832 copies os.environ verbatim). Agent re-arms every ~10 min, burns
   turns/budget (up to ~$40/quiet rotation), never emits its digest, and is force-killed at
   ROTATION_HOURS+300s (journal: dispatch→unclean exactly 14702s). Post-kill backoff grows
   30s→240s+ (harness.py:3816-3820), adding L1 pickup latency.
   Fix direction (audit-preferred): add `--timeout <secs>` to watcher.py (inotify.read(timeout=ms),
   exit on expiry) + SKILL.md loop change to recheck the rotation clock and exit cleanly with
   digest; alternative/complement: inject BASH_MAX_TIMEOUT_MS sized to the rotation in
   `_run_watcher_rotation`.
2. **L1 drain-before-up race** — watcher.py has no initial scan; the L1 skill drains *then* arms
   (Main Loop steps 3→8), so an L1 born in the gap waits for the next unrelated L1 (the L2 analog
   sat 21h, esc-1573-8). Fix: mirror the L2 skill's drain-after-up ordering; optionally an
   initial scandir-print-and-exit in watcher.py.
3. **Queue-root hygiene** — 683 resolved/dismissed orphans in the queue ROOT (676 with no archive
   twin) tax every `get_pending()` ~28ms warm (paid per drain/submission/promote/steward tick);
   7 cross-tier duplicates log WARNINGs; 11 loose files at archive/ top level escape
   `prune_archive`. `escalation.sweep --apply` already implements reconciliation but is wired
   nowhere. Fix: one-time sweep + wire into server startup or a daily user-timer; extend the
   reaper to root-orphans and loose archive files.
4. **`add_members_to_l2` clobber race** (queue.py:476-503, documented not-concurrency-safe) —
   reachable because nothing prevents two L2 watcher sessions or an L2 session concurrent with
   the auto-watcher. Fix: per-file flock or CAS-with-retry on member append; optional advisory
   session lockfile.
5. **ntfy priority inversion** — watcher.py:29 maps only `severity=='blocking'` to urgent, so
   born-at-L2 critical/urgent (the only class the L2 skill promises will interrupt an AFK human,
   SKILL.md:194-195) push as `[INFO]`/default. Fix: `severity in BORN_AT_L2_SEVERITIES | {'blocking'}`.
6. **Doc truth** — drop the obsolete fd-pool rationale from escalation-watcher-auto/SKILL.md:230
   (contradicts escalation-watcher/SKILL.md:578; the leak was an interactive-session
   run_in_background artifact); add a watcher.py module docstring stating the two load-bearing
   invariants (all writers atomic tmp+rename; watcher is wake-signal-only, drains are
   authoritative).

Gate pre-answers: G1 consumer = the orchestrator operator + the L1 supervisor itself (cost/latency)
and AFK watcher sessions. G2 leaf signal = journalctl shows clean rotation exits with digests
(0 force-kills over a window); a synthetic L1 filed during watcher startup is drained without a
second L1 firing. G3 substrate = all anchors above verified 2026-06-04. G6 premise = live journal
evidence (10/10 unclean rotations). Verified non-issues (do NOT re-open): inotify partial-read
(all esc-*.json writers route through atomic tmp+rename, incl. fused-memory recon);
queue.py archive-scan TODOs (~2ms at live volume).

## Brief 2 — PRD: B3 low-risk auto-unblock hardening (PRD-2)

Issues (priority order):

1. **No mechanical freshness anchor.** Proposals record no head_sha/main_sha
   (dry_run_unblock.py:271-278; output schema dry_run_unblock.py:25-44 has
   additionalProperties:False so a sha cannot even round-trip); both gates are prose-only
   (escalation-watcher/SKILL.md:205; unblock-low-risk/SKILL.md:35-38, :120-122 explicitly calls
   sha “future hardening”). Fix: record worktree HEAD sha + main sha into every proposal entry at
   investigation time; make freshness a hard git-log ABORT in unblock-low-risk (no commits on the
   branch since recorded head; no conflicting main movement). Correctness today is backstopped by
   the merge queue's post-merge re-rebase+verify — the cost is false aborts → human round-trips.
2. **Cap shape is wrong on both axes.** “<3 per session, counted at launch, aborts spend slots”
   lives only in the L2 watcher's context (escalation-watcher/SKILL.md:206-210, 226-227,
   235-237, 513-517): it resets on every rotation/restart (leaky as a runaway guard) yet strands
   everything after slot 3 within a durable session (an AFK weekend with 8 low-risk blocks
   strands ≥5). Fix: per-task cap=1 (already implied by the in-flight skip) + a durable rolling
   per-24h global cap persisted outside context (dated state file or task metadata); do not
   charge clean no-op aborts.
3. **B3 is gratuitously AFK-only** (escalation-watcher/SKILL.md:240-242). Every safety rail in
   unblock-low-risk is posture-agnostic (release_workflow grip-check, scoped edits, full verify,
   merge-queue-only, one-attempt abort-on-doubt); only framing prose says “no human is watching”.
   Attended mode currently costs one human round-trip per low-risk fix. Fix: attended-mode B3
   behind a config flag with mandatory post-hoc notification (diff + merge sha) and the existing
   revert path.
4. **Proposal lifecycle**: `dry_run_proposals` is append-only with no pruning
   (dry_run_unblock.py:199-203); fresh investigation only on actual re-block
   (workflow.py:5375, dedup at :5736); nothing re-validates at launch. Fix: pair with the sha
   anchor — cheap git-log drift check at B3 launch, re-run the (~600s) investigation only on
   drift; cap the list length (keep last N).

Explicitly rejected by the audit (do not revisit): moving B3 execution down to L1 — it would
breach the L1 skill's hard safety envelope (no code edits, no merge-queue, no background
subprocess; escalation-watcher-auto/SKILL.md:10-17) for one queue-hop of latency.

Gate pre-answers: G1 consumer = AFK (and, behind the flag, attended) L2 watcher sessions; the
human who returns to a digest instead of a stranded pile. G2 leaf signal = a synthetic stale
proposal hard-aborts with a git-anchored reason; a fresh one merges via the queue; cap state
survives a session restart. G3 substrate = anchors verified 2026-06-04; merge-queue post-merge
re-rebase+verify confirmed as the correctness backstop. G4 = this brief's edits to
escalation-watcher/SKILL.md are confined to the B3 subsection + AFK shift 2 (see register).

## Brief 3 — PRD: escalation re-pend state machine & merge gating (PRD-3)

**G5 applies: design-first.** These issues are one state machine; decide the target semantics
before decomposing. High stakes: one issue is correctness-class.

Issues (priority order):

1. **Born-at-L2 never gates the workflow or merge (latent correctness hole).** All gates filter
   `severity=='blocking' and level==0` (workflow.py:3093-3096 post-implementer, :3442-3445
   post-debugger, :1186-1189 MERGE-entry); a critical/urgent level-2 record fails both
   predicates; the merge worker reads no escalations. So the highest-severity class is the only
   one that cannot stop a merge — inverse of the documented semantics
   (escalation-watcher/SKILL.md:15, server.py:222-224/285-287). Currently dormant (no shipped
   prompt files task-attached critical; only the harness watcher-outage sentinel path,
   harness.py:2212-2234, uses born-at-L2) — activates silently on any prompt change. Fix: extend
   the three gates with `or e.severity in BORN_AT_L2_SEVERITIES or e.level >= 2`; decide intent
   for agent-facing critical (allow + document in roles.py, or reject for non-sentinel task ids).
   Side benefit: stops the verify/debugger budget grind (~$7-8/cycle) after a critical escalation.
2. **`terminate=true` is a broken primitive.** Dismissal sets only `status='dismissed'`
   (queue.py:337); every flip gates on `'resolved'` (harness.py:4170, :4207 — comment at
   4198-4199 says dismissed = “abandon the task; leave it blocked”). The blocked task then trips
   Fix#1b within ≤900s, which re-files `task_failure`/`manual_intervention` → the auto-watcher
   promotes it straight back to a human L2 (escalation-watcher-auto/SKILL.md:314-341): the human
   who dismissed is re-asked, context lost. Also: a blocked task holds no dispatch slot, so
   `terminate=true` buys nothing for independent work vs leave-pending (strictly worse — loses
   the one-hop resolve→re-pend and the audit trail). The real abandon primitive is
   `set_task_status(id,'cancelled')` (terminal; skipped by the flip harness.py:4226-4232 and by
   Fix#1b's blocked-only gate); re-run-from-scratch is `set_task_status(id,'pending')`.
   Fix: (a) rewrite escalation-watcher/SKILL.md:170-179 + :553-557 and the auto-watcher
   scope_violation/dependency_discovered flows (escalation-watcher-auto/SKILL.md:247-291, same
   wrong “will be rescheduled” claim); (b) make the Fix#1b backstop L1 mechanically resolvable —
   e.g. a dedicated `stranded_blocked` category the auto-watcher auto-resolves (triggering
   Fix#1a's re-pend) instead of `task_failure`/`manual_intervention`, reserving humans for
   genuinely re-failed tasks; (c) consider an explicit operator “parked” marker that Fix#1b
   respects.
3. **No cross-incarnation re-block guard.** All thrash counters are failure-mode-specific
   (infra-resume workflow.py:2451-2557 gated on a resolved L0 of category infra_issue at :2520;
   no-plan :2373-2421; merge-thrash :2589-2644; verify-signature history per-run-ephemeral
   :383-387). A cascade-re-pended task that re-fails loops blocked→L2→pending→blocked unbounded,
   one full agent budget + a human round-trip per loop. Fix: persisted per-task
   `total_blocked_redispatches` in metadata, incremented at the blocked→pending flip; small
   threshold (~3) → `_mark_blocked(escalate_to_human=True)`-style “persistent re-block” L1.
   (Follow the existing `_check_*_thrash` helper shape: counter+signature, reset to 1 not 0.)
4. **Flip durability.** The blocked→pending flip is a scheduled coroutine fired after the durable
   resolve (queue.py:345→351; silent coro drop when the loop is closed, harness.py:4088-4093).
   Crash in the window ⇒ resolved-on-disk + task blocked + no pending escalation ⇒ only Fix#1b
   recovers (a full second escalation round-trip), and mid-run Fix#1b fires at most every 900s.
   Fix: startup replay — scan recently archived resolved L1s whose task is still blocked with no
   pending escalation and call `_cascade_unblock_member` directly; consider an immediate one-off
   sweep trigger when flips are scheduled near shutdown. Add the missing restart-window
   regression test (none exists; test_cascade_unblock.py covers only in-process resolutions).
5. **Small gates** (fold in): Fix#1b's `_workflow_cancel_at` gate is membership-not-age
   (harness.py:1809 vs the 30s grace honoured at :1557-1565) — suppresses recovery up to a full
   sweep; `_escalation_events` is registered deep in the slot coroutine (harness.py:2356) not at
   dispatch (:892), leaving a sub-second window where Fix#1a can race a re-dispatched workflow.
6. **Doc truth owned by this PRD**: `resolve_issue` docstring (server.py:338-339) claims the
   resolution text reaches the agent — true only on the L0 live-workflow path
   (workflow.py:4737-4782 → :1155-1160); born-at-L2 “routes straight to a human” framing implies
   merge protection that doesn't exist until issue 1 lands; the L2 skill's entire
   `review_suggestions` handler (escalation-watcher/SKILL.md:257-368) is unreachable dead prose —
   live path routes suggestions as curator tickets (workflow.py:5923-6037, called at :2997, no
   escalation file); fallback files level-0 consumed by the steward (steward.py:222-234) — delete
   the handler (one-line routing-bug note instead).

Gate pre-answers: G1 consumer = the L2 human/watcher session (decisions become durable), the
scheduler (tasks re-enter or terminate promptly), and budget (no unbounded loops). G2 leaf
signal = e.g. a test where an agent-filed critical escalation blocks MERGE; terminate=true on a
synthetic L2 leads to a cancelled (not re-asked) task; a 3x re-blocked task escalates to human
instead of looping; restart between resolve and flip recovers without a second human round-trip.
G3 substrate = all anchors verified 2026-06-04 (audit re-traced adversarially). G6 premise =
traced incidents: 3576 strand (2026-05-29), esc-1888-57 phantom-halt class. Decide the re-pend
semantics ONCE; items 2b and 4 partially overlap (startup replay reduces how often Fix#1b
matters; the category change alters what happens when it does) — design them together.
