# R1

A coalesce train is formed inside the merge lane from singles waiting in the normal-lane buffer. SpeculativeMergeWorker._maybe_coalesce_waiting_singles filters candidates, _stack_coalesce_train selects members and calls GitOps.stack_train_branches, and a GroupMergeRequest with a 'coalesce-' train id is appended to the buffer tail. Each absorbed single's future is resolved 'superseded' with superseded_by=train_id and its request id is retired. Its journal row is removed by the _on_terminal callback and its registry slot is released by the future's done-callback. The train itself is never journaled, never gets a merge_finalized event, and nothing awaits its future. The coalesce train has no consumer other than the merger loop. After SpeculativeMergeWorker._merger_loop runs _do_train_merge, it applies one-strike marking and the unwind purely off the returned outcome, and the future is resolved through the verifier passthrough. The whole design assumes every member is a task parked 'merge-deferred' by TaskWorkflow._handle_superseded. That assumption shows up in the status pre-check (step a) and in MemberRedriver.redrive, which acts only on merge-deferred members. It also shows up in restore_pre_stack_tips (restorable statuses are merge-deferred, pending and blocked) and in AbandonedMemberSweep, which scans only merge-deferred rows. The harness callback factory has one escape hatch: ids absent from the scheduler are synthesised as 'merge-deferred' and their done and re-drive writes are no-ops. So a member with no task at all passes the pre-check, while an MCP single whose task sits at blocked, deferred, pending or in-progress deterministically fails it. That failure is a 'blocked' train_incomplete outcome, which also strikes every member for seven days and triggers an unwind that does nothing for the non-parked members. Every durable trace of an absorbed MCP single disappears at absorption: journal row, registry slot, and a terminal 'superseded' record pointing at a train id that merge_status cannot resolve. If the train is lost, nothing re-enqueues the MCP merge. Several lane mechanisms key on task_id rather than the request's branch and worktree. These are the stack worktree path, the branch name, the line-range probe and the re-drive. The MCP merge_request supplies task_id, branch and worktree independently, so these are unsafe for it. merge_cancel's waiter path (MCP only) bypasses the lane's train and coalescing refusal. WIP halts raised by a coalesce train have no owner, because the only owner-registering consumer is the declared-train tip workflow.

## 2. Absorption of singles (future, registry, journal, train identity)
- [read] For each survivor, if its future is not done the lane sets MergeOutcome('superseded', superseded_by=train_id). It then retires the request's own request_id unconditionally via _retire_item (lifecycle TERMINAL, _live_items popped). It emits a train_coalesced event with absorbed_request_ids, tip_task_id, ejected, size and the exclusions list.  — `orchestrator/src/orchestrator/merge_lane/worker.py::SpeculativeMergeWorker._stack_coalesce_train; orchestrator/src/orchestrator/merge_lane/worker.py::SpeculativeMergeWorker._retire_item`
- [read] Journal row. The single was journaled in _buffer_owned_request, and its _on_terminal done-callback removes the row on any terminal outcome except a cancelled future or blocked+SHUTDOWN_REASON. 'superseded' therefore removes the row (asynchronously, via the callback) when the train forms. The GroupMergeRequest is never journaled (queue_store.record skips it) and not added via _buffer_owned_request.  — `orchestrator/src/orchestrator/merge_lane/worker.py::SpeculativeMergeWorker._buffer_owned_request; orchestrator/src/orchestrator/merge_lane/queue_store.py::MergeQueueStore.record`
- [read] Registry slot. InFlightMergeRegistry.acquire adds a done-callback that releases the per-branch slot when the future resolves, so absorption frees the MCP branch slot. The train is never acquired in the in-flight registry (only in the lifecycle registry via _register_item).  — `orchestrator/src/orchestrator/merge_lane/types.py::InFlightMergeRegistry.acquire; orchestrator/src/orchestrator/merge_lane/worker.py::SpeculativeMergeWorker._stack_coalesce_train`
- [read] What an MCP poller sees. The submitter's own request resolves 'superseded' with superseded_by='coalesce-...'. merge_request(wait_secs>0) returns it verbatim, and merge_status reports the terminal state 'superseded' (from the merge_finalized row written by enqueue_merge_request's _on_finalized). Polling the train id returns stale_record with reason coalesce_train_id, because the id resolves only as other rows' superseded_by. There is no merge_finalized row, retention record or alias for the train, because the GroupMergeRequest never passes through enqueue_merge_request.  — `orchestrator/src/orchestrator/merge_lane/worker.py::enqueue_merge_request; escalation/src/escalation/server.py::_durable_history; shared/src/shared/merge_state.py::MergeReason.coalesce_train_id`
- [read] Consumer-side contract already exists for a workflow-less submitter: skills/merge-queue/SKILL.md tells the caller never to resubmit or direct-merge on 'superseded', to follow the train via the branch handle and git ancestry, and to rely on the scheduler status becoming 'done' (it says the lane flips the member automatically). - [read] Absorbed member timing. ## 3. The slot: _do_train_merge exits and what follows each
- [read] Dequeue. In _merger_loop a GroupMergeRequest first parks behind an unadvanced predecessor (_await_unadvanced_predecessor), then is stood down if admission is halted (a coalesce train is dissolved, a declared one requeued), then runs _do_train_merge inline in the merger coroutine. Its outcome rides the verifier queue as DecidedItem.immediate_outcome, and the passthrough branch sets req.result and retires the item.  — `orchestrator/src/orchestrator/merge_lane/worker.py::SpeculativeMergeWorker._merger_loop; orchestrator/src/orchestrator/merge_lane/worker.py::SpeculativeMergeWorker._stand_down_train`
- [read] Two post-outcome hooks in the merger loop run only for train ids with the 'coalesce-' prefix. (1) outcome.status in {'blocked','error'} runs _mark_coalesce_derailed(member_task_ids). (2) outcome.status != 'done' runs _unwind_coalesce_train(req, actual_main). Both run BEFORE the verifier put, so custody still holds the members during the unwind. TRAIN_PARTIAL_FLIP returns 'done' and so triggers neither.  — `orchestrator/src/orchestrator/merge_lane/worker.py::SpeculativeMergeWorker._merger_loop`
- [read] Exit: loop-breaker. If post-merge verify timeouts for the tip task_id reach MAX_POST_MERGE_VERIFY_TIMEOUTS, the train returns _abandon_outcome ('blocked'), so one-strike and unwind follow.  — `orchestrator/src/orchestrator/merge_lane/worker.py::_do_train_merge`
- [read] Exit: status pre-check (step a). status_check(member_task_ids) must give exactly 'merge-deferred' for every member. Otherwise each non-matching member emits train_member_deferred, and the result is MergeOutcome('blocked', reason='Train merge rejected: not all members are merge-deferred: member X is Y') with an OutcomeKind.train_incomplete attempt. Because the outcome is 'blocked', hook (1) one-strikes ALL members and hook (2) unwinds. For a declared train the tip workflow parks and re-fires on this reason. For a coalesce train nothing consumes it.  — `orchestrator/src/orchestrator/merge_lane/worker.py::_do_train_merge; orchestrator/src/orchestrator/workflow.py::TaskWorkflow._maybe_enqueue_group_merge`
- [read] The harness status_check queries scheduler.get_statuses. On a read error it returns the partial dict (the pre-check then sees '<missing>'). When the read succeeds it synthesises 'merge-deferred' for every id the scheduler omits (non-task members, e.g. MCP branches). mark_member_done and redrive_member are no-ops for ids absent from the scheduler.  — `orchestrator/src/orchestrator/harness.py::build_train_callback_factory`
- [read] Exit: tip rebase conflict ('rebase_onto_main(req.worktree)' False) returns blocked 'Train rebase conflict...' with train_derailed and train_rebase_conflict events. Exit: merge_to_main conflict or failure returns blocked with train_derailed. A None merge_commit or merge_worktree raises RuntimeError (see unwind-skipping exceptions below).  — `orchestrator/src/orchestrator/merge_lane/worker.py::_do_train_merge`
- [read] Exit: verify. _leased_train_verify runs the workspace verify on a leased host (remote only for trains of at most 2 members, local fallback on transport fault). A red verify becomes _derail_on_train_verify_failure: blocked, with a structured red tagged TRAIN_VERIFY_FAILED_REASON_PREFIX for δ attribution (declared-train workflow only). A coalesce train has no attribution, so one-strike hits every member.  — `orchestrator/src/orchestrator/merge_lane/worker.py::_leased_train_verify; orchestrator/src/orchestrator/merge_lane/worker.py::_derail_on_train_verify_failure; orchestrator/src/orchestrator/workflow.py::TaskWorkflow._attribute_train_failure`
- [read] Exit: CAS. _advance_train journals a LandedRow (keyed by the TIP task_id only) then advance_main(reverify_on_rebase=True) each pass. ## 5. Restart behaviour
- [read] (a) A train waiting in a lane buffer. Nothing about it is durable: the train is not journaled and each absorbed single's journal row was removed at absorption. A graceful stop() drains lane buffers and sets blocked+MERGE_WORKER_SHUTDOWN_REASON on the train future with no unwind and no re-drive. Members stay stacked and (if workflow-parked) merge-deferred. Recovery for workflow members is the later AbandonedMemberSweep. If a restart drain sets an admission halt first, _dissolve_coalesce_trains_if_halted unwinds the train properly. A crash within the window before the async journal-remove callback runs would instead leave the journal rows, which recover as solo requests with awaited_by_workflow=False.  — `orchestrator/src/orchestrator/merge_lane/worker.py::SpeculativeMergeWorker.stop; orchestrator/src/orchestrator/merge_lane/queue_store.py::recover_pending_merges; orchestrator/src/orchestrator/merge_lane/worker.py::SpeculativeMergeWorker._dissolve_coalesce_train`
- [read] (b) A train mid-verify. It runs inline in the merger coroutine, with no InflightEntry (task 5245 note). A cancelled merger resolves it blocked+SHUTDOWN via _resolve_merging_requests in the merger's finally block. The unwind is not run because the cancel is a BaseException passing the code after _do_train_merge. Members stay stacked on rewritten refs with no durable record, and the tip's LandedRow exists only if CAS had begun.  — `orchestrator/src/orchestrator/merge_lane/worker.py::SpeculativeMergeWorker._merger_loop; orchestrator/src/orchestrator/merge_lane/worker.py::SpeculativeMergeWorker._verifies_in_flight`
- [read] (c) Between CAS and the flip loop. Main has the landing; only the tip's LandedRow survives, and the members' tasks sit merge-deferred. ## 8. Declared (non-coalesce) trains vs coalesce trains
- [read] Formation. A declared train is formed by TaskWorkflow (metadata.train, scheduler.tasks_by_train, _select_train_members and its own stacking in workflow.py). ## HAZARDS
- **Deterministic train_incomplete for any MCP single whose task is not merge-deferred** — _do_train_merge requires status_check(...) == 'merge-deferred' for every member. An MCP single's task sits at blocked, deferred, pending or in-progress, so the pre-check fails every time. The result is a 'blocked' train_incomplete outcome that no workflow re-fires. Only a member with NO scheduler task passes, via the harness synthesis. — `orchestrator/src/orchestrator/merge_lane/worker.py::_do_train_merge; orchestrator/src/orchestrator/harness.py::build_train_callback_factory`
- **train_incomplete poisons every member with a 7-day one-strike** — _merger_loop one-strikes member_task_ids for any 'blocked' outcome of a coalesce train, and train_incomplete is 'blocked'. A single MCP member that cannot pass the pre-check therefore strikes its workflow-awaited co-members too. They are excluded from coalescing for _COALESCE_DERAIL_TTL, and entries are never discarded earlier. The same blanket marking applies to a verify-red train, since coalesce trains have no attribution step. — `orchestrator/src/orchestrator/merge_lane/worker.py::SpeculativeMergeWorker._merger_loop; orchestrator/src/orchestrator/merge_lane/worker.py::SpeculativeMergeWorker._mark_coalesce_derailed`
- **The unwind and redrive are inert for non-parked members, so an MCP member is never re-submitted** — MemberRedriver.redrive returns NOT_PARKED for any member whose status is not merge-deferred, so no re-pend and no re-submit occurs. The only repair for an MCP member is restore_pre_stack_tips, and that is skipped for a task at 'deferred' (the hand-carry guard status) or 'in-progress'. Those members stay stacked on a co-member's commits. The submitter's merge request has already left the journal and registry, so the merge is lost until a human resubmits. — `orchestrator/src/orchestrator/merge_lane/member_redrive.py::MemberRedriver.redrive; orchestrator/src/orchestrator/merge_lane/coalesce_unwind.py::_RESTORABLE_STATUSES`
- **Train outcome has no consumer and no durable record visible to the MCP submitter** — The absorbed MCP single resolves terminal 'superseded' (superseded_by=coalesce-...) at formation. The train's future has no done-callback and no merge_finalized row. merge_status(train_id) returns stale_record/coalesce_train_id, and the train's later outcome (or dissolution) reaches nobody. The submitter's only handle is git ancestry plus the task status, and the skill's contract expects the lane to flip the task to done, which it cannot for a non-merge-deferred task. — `orchestrator/src/orchestrator/merge_lane/worker.py::SpeculativeMergeWorker._stack_coalesce_train; escalation/src/escalation/server.py::_durable_history; skills/merge-queue/SKILL.md`
- **Absorption destroys every durable trace of an MCP single and no recovery path reaches it** — The journal row is removed by _on_terminal on 'superseded', the registry slot is released by the future done-callback, and the lifecycle entry is retired. The train is never journaled, and stop(), a mid-verify cancel or a crash leaves members stacked. AbandonedMemberSweep and the dissolve path act only on merge-deferred members. An MCP member that never parked is silently dropped from the queue. A workflow member has the merge-deferred sweep as its backstop. — `orchestrator/src/orchestrator/merge_lane/worker.py::SpeculativeMergeWorker._buffer_owned_request; orchestrator/src/orchestrator/merge_deferred_recovery.py::AbandonedMemberSweep.run_pass`
- **Stacking and redrive key on task_id, not on the request's branch/worktree** — stack_train_branches requires worktree_base/<task_id> and branch_prefix+<task_id>. restore_pre_stack_tip, forget_stack_bases and MemberRedriver (is_ancestor on prefix+mid) also use the id. The tip keeps tip_req.branch and tip_req.worktree. MCP merge_request takes task_id, branch and worktree independently (often a hand-carry worktree outside .worktrees/<id>). So a mismatching submission is ejected on 'worktree not found', or stacked and restored against the wrong branch. Ejected members stay solo and the train may never form. — `orchestrator/src/orchestrator/git_ops.py::GitOps.stack_train_branches; orchestrator/src/orchestrator/merge_lane/member_redrive.py::MemberRedriver._redrive_parked; escalation/src/escalation/server.py::merge_request`
- **The line-range stackability filter is a no-op for every member, MCP or not** — get_changed_line_ranges is called with a bare task id. The diff against a bare ref errors (rc 128, verified by running git here), stdout is empty, and ranges are {}. _line_ranges_stackable then returns True for every pair. Conflicts are caught only by the stacking rebase. For MCP singles with task_files=None this removes the only cheap overlap screen. — `orchestrator/src/orchestrator/git_ops.py::GitOps.get_changed_line_ranges; orchestrator/src/orchestrator/merge_lane/worker.py::SpeculativeMergeWorker._stack_coalesce_train`
- **The lane rewrites a live interactive worktree in place** — stack_train_branches rebases each successor's worktree onto its predecessor's branch, and _do_train_merge rebases req.worktree (the tip) onto main. An MCP submitter (an interactive /unblock or hand-carry session) may still be working in that worktree. The only guard is task status in restore, which does not cover 'deferred' or 'in-progress'. Whether rebase_onto_main refuses a dirty worktree was not read. — `orchestrator/src/orchestrator/git_ops.py::GitOps._stack_member; orchestrator/src/orchestrator/merge_lane/worker.py::_do_train_merge`
- **merge_cancel on an MCP single bypasses the coalescing and train refusal** — The server's waiter path cancels rec.future directly. The lane refusal in cancel_request (_train_cancel_refusal, _coalescing_ids) is reached only on the no-waiter path. An MCP single cancelled while _stack_coalesce_train is awaiting is still in survivor_reqs, so set_result is skipped (future done) but the branch is stacked and lands. Today it is latent only because MCP singles are excluded. — `escalation/src/escalation/server.py::merge_cancel; orchestrator/src/orchestrator/merge_lane/worker.py::_train_cancel_refusal; orchestrator/src/orchestrator/merge_lane/worker.py::SpeculativeMergeWorker._stack_coalesce_train`
- **After absorption an MCP submitter has no cancel or abort** — The single's future is done and the waiter is gone, so merge_cancel answers 'Request already finalized' (superseded). The train id is refused with TRAIN_CANCEL_UNSUPPORTED and _do_train_merge has no abandonment checkpoint. The only remedy is blocking the member tasks, which an MCP member with no workflow may not have. — `escalation/src/escalation/server.py::_cancel_in_lane; orchestrator/src/orchestrator/merge_lane/worker.py::_train_cancel_refusal`
- **WIP halts caused by a coalesce train are owner-less** — _map_advance_failure calls halt_for_wip (all lanes, owner None). Only TaskWorkflow._escalate_train_halt registers a halt-owning L1 (set_halt_owner), and only for a declared train whose tip workflow awaits the result. For a coalesce train no workflow awaits, and an MCP-only train has no re-dispatched workflow to ever hit the halt barrier, so the queue stays halted until an operator unhalts it. — `orchestrator/src/orchestrator/merge_lane/gates.py::_map_advance_failure; orchestrator/src/orchestrator/workflow.py::TaskWorkflow._escalate_train_halt`
- **Exceptions out of _do_train_merge strand members with no unwind or one-strike** — WorktreeMissing (tip worktree deleted; for MCP it is a submitter-chosen path), the None merge_commit RuntimeError, or any merger error are caught by the loop's generic handlers, which only set the train future to 'blocked'. The unwind and one-strike sit after the call in the same try and are skipped, so every member stays stacked. — `orchestrator/src/orchestrator/merge_lane/worker.py::SpeculativeMergeWorker._merger_loop`
- **Post-landing flips assume merge-deferred to done** — mark_member_done runs mark_done(kind='merged') after a successful pre-check, so every member it flips was merge-deferred. The lane never writes done for a pending, blocked or deferred MCP member, and the submitter stamps by hand today. Only the tip's LandedRow reconcile can mark done: RC-2 for a tip at 'pending', pruned and not done for 'blocked' or 'deferred' (both preserve statuses). A no-task member's mark_member_done is a silent no-op. — `orchestrator/src/orchestrator/harness.py::build_train_callback_factory; orchestrator/src/orchestrator/merge_lane/worker.py::reconcile_landed_row`
- **Non-tip members of a landed train may not be ancestors of main** — The train lands the tip branch rebased onto main, which rewrites commit SHAs when main moved. Non-tip member refs keep their pre-rebase stacked SHAs. After TRAIN_PARTIAL_FLIP, a landed-then-unwound outcome, or a crash before the flip loop, MemberRedriver finds such a member not on main and re-pends it (workflow members) for a redundant solo re-merge instead of found_on_main. For an MCP member (never parked) it would be left without any status flip. — `orchestrator/src/orchestrator/merge_lane/member_redrive.py::MemberRedriver._redrive_parked; orchestrator/src/orchestrator/merge_lane/worker.py::_do_train_merge`
- **Train landings skip single-path post-landing hooks that MCP landings use today** — _note_merge_landing and the _on_merge_landed hook (offline deep-test lane trigger) are called only at single-request finalize sites. _do_train_merge and the passthrough branch call neither, so moving MCP landings into trains drops those side effects. — `orchestrator/src/orchestrator/merge_lane/worker.py::SpeculativeMergeWorker._finalize_inflight; orchestrator/src/orchestrator/merge_lane/worker.py::_do_train_merge`
- **awaited_by_workflow is a per-request flag, not the registry fact, and it is lost across restart** — The coalescer reads only MergeRequest.awaited_by_workflow, which a recovered journal request resets to False. A workflow attached to an MCP-dispatched primary still looks non-workflow to the coalescer, while an MCP waiter attached to a workflow primary is absorbed along with it (attached-waiter mirroring was not read). — `orchestrator/src/orchestrator/merge_lane/worker.py::SpeculativeMergeWorker._coalesce_exclusion_reason; orchestrator/src/orchestrator/merge_lane/types.py::InFlightMergeRegistry.has_workflow_waiter`
