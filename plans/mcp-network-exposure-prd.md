## 1. Consumer + user-observable surface (G1)

**Consumer:** the operator's security posture on the workstation, and every existing local consumer of the factory's servers, which must keep working unchanged. Those consumers are enumerated and all on this host: the nine orchestrators (`orchestrator/src/orchestrator/mcp_lifecycle.py::McpLifecycle.mcp_config_json` builds `fused_memory.url + '/mcp'`; dark-factory's yaml says `http://localhost:8002`, the eight sibling yamls `http://127.0.0.1:8002` or `localhost`), interactive and T3 sessions (`.mcp.json`, `recon-watch/mcp.json`: `127.0.0.1`), the dashboard (`dashboard/src/dashboard/config.py::DEFAULT_FUSED_MEMORY_URLS` = `localhost:8002`; `_discover_escalation_urls` default host `127.0.0.1`), the reconciliation stage agents (`fused-memory/src/fused_memory/reconciliation/stages/base.py` builds `http://127.0.0.1:<recon_report_port>/mcp/`), the watchdog (`scripts/orchestrator-watchdog.py::FUSED_MEMORY_HEALTH_URL`, `127.0.0.1`), the fused-memory unit's own `ExecStartPre` port wait (`127.0.0.1:6379 127.0.0.1:6333`), and fused-memory's store clients (`fused-memory/config/config.yaml` `graphiti.falkordb.uri` default `redis://localhost:6379`, `mem0.qdrant_url` default `http://localhost:6333`). `getent ahosts localhost` on this host resolves to `127.0.0.1` only (`/etc/hosts` maps `::1` to `ip6-localhost`), so every `localhost` consumer is an IPv4 loopback consumer.

**No remote consumer exists.** The one cross-host path, the laptop verify leg (`orchestrator/src/orchestrator/verify_runner.py::RemoteRunner`, `orchestrator/src/orchestrator/remote_gate.py`), is ssh plus git push and names no MCP endpoint; the laptop's own fused-memory unit is deliberately disabled (SB §"Remote consumers today and planned").

**User-observable surface after this PRD lands:**

1. `ss -ltn` on the workstation shows no factory listener on `0.0.0.0` or `[::]`: `127.0.0.1:8002`, `127.0.0.1:8003`, `127.0.0.1:8103`, `127.0.0.1:81xx` for every escalation queue, and `127.0.0.1:6379`, `127.0.0.1:6333`, `127.0.0.1:6334` for the two containers (`docker inspect -f '{{json .NetworkSettings.Ports}}'` shows `HostIp` `127.0.0.1` only, no `::` entry).
2. A TCP connect to any of those ports on the workstation's LAN address (`192.168.1.105`), its tailnet address (`100.107.28.56`) or any of its global IPv6 addresses is **refused**, and a connect on `127.0.0.1` is **accepted**. `scripts/check_network_exposure.py` (new, §9 leaf α) performs exactly that probe and exits 0; `scripts/setup-host.sh` §11 "Health checks" runs it and fails loudly when it does not.
3. Every consumer in the list above works unchanged: `curl -sf http://localhost:8002/health` answers, every `orchestrator-*.service` stays `active`, the dashboard's fused-memory and escalation panels stay green, a reconciliation cycle completes against `:8003`.
4. The change is a hard boundary (a bind), not a check a client can omit (a header).

The signals are presence/absence of listeners and accept/refuse outcomes, not thresholds (G6).

## 3. Approach

Three committed facts become loopback in one leaf (β): `scripts/fused-memory.socket.template` `ListenStream=127.0.0.1:8002`, `fused-memory/config/config.yaml` `server.host: "127.0.0.1"` (which also re-binds `:8003`), `fused-memory/docker/docker-compose.yml` `ports` with a `127.0.0.1:` host prefix on all three mappings; `ServerConfig.host` default follows. One committed deploy script applies them to the running host in one recon-aware stop/start and proves the result with the exposure check (α). One deterministic auto-deploy task (γ) runs that script and carries the done-provenance.

**Contract of the exposure check (`scripts/check_network_exposure.py`, leaf α):**

- Port set = the `listen` ports of every `fused-memory.socket` and `orchestrator-*.socket` row from `systemctl --user list-sockets -o json` ∪ a static table `{8003: fused-memory recon-report (ServerConfig.recon_report_port), 6379: compose falkordb, 6333/6334: compose qdrant}`. The static table is pinned to its homes by a test (compose `ports` and the `ServerConfig.recon_report_port` default), so the table cannot drift from them unnoticed (*SPOT*; INV-5).
- Address set = every non-loopback IPv4 and IPv6 address from `ip -j addr` (today: `192.168.1.105`, `100.107.28.56`, the three global IPv6 addresses, and the docker bridge gateways, which must also refuse).
- Verdict = for every (address, port): TCP connect **refused** (ECONNREFUSED; a timeout is a failure too, named as such), and for every port: connect on `127.0.0.1` **accepted**. Exit 0 iff all hold. Every emitted line carries one tag (`[network_exposure]`, the `scripts/systemd_unit_parity.py::emit` convention), and a failure line names the port, the address that accepted, and the owner from the port set (unit name or compose service) (INV-2).
- Stdlib only, system `python3`, no sudo, no firewall reads (the rules are root-only and docker bypasses them anyway; the connect probe measures the boundary that actually holds).
- Callers: `scripts/setup-host.sh` §11 (fails the install's health checks on a non-zero exit, believed only when the tag is present, as for the parity family) and `scripts/restart-fused-memory.sh --rebind-socket` (post-condition).

**Contract of the apply path (`scripts/restart-fused-memory.sh --rebind-socket`, leaf β).** The one new mode of the existing, committed, executable restart script (mode `100755` on `main`), and the script γ's `before_done` names. Decided at decompose (§13): `submit_task`'s `before_done` guard (`fused-memory/src/fused_memory/middleware/deterministic_task_guard.py::_validate_before_done`) requires the script to exist and be executable **under `project_root` at filing time**, so γ cannot name a file β has not yet landed; routing γ through the restart script keeps the mechanism and the provenance intact, and the γ → β edge guarantees the flag exists on `main` before γ dispatches (today the script rejects the flag with its usage line, exit 1). In order, `--rebind-socket`:

1. refuses (non-zero, tagged) when `systemctl --user is-active fm-staleness-redeploy.service` reports active — that name is a **transient** `systemd-run --unit=` unit minted by `scripts/orchestrator-watchdog.py::FM_STALENESS_REDEPLOY_UNIT`, not a unit file, so it is absent from `list-units --all` between redeploys and `is-active` answers `inactive` then; do not "fix" the missing file;
2. `install -m 0644 scripts/fused-memory.socket.template ~/.config/systemd/user/fused-memory.socket` (verbatim, as `setup-host.sh` §4; the service unit is not touched, so the "patch installed units surgically" rule is satisfied by construction) and `systemctl --user daemon-reload`;
3. the existing recon-busy gate (`--now` still bypasses it), then the documented stop-then-start — `systemctl --user stop fused-memory` (its `ExecStopPost` stops the socket) and `systemctl --user start fused-memory.socket fused-memory` — in place of the plain `systemctl --user restart` the other modes issue, so the socket unit rebinds and the `ExecStartPre` AOF gate recreates the containers;
4. the existing post-start `/health` wait;
5. `scripts/check_network_exposure.py` as the post-condition; its exit status is the mode's.

`--drain`, `--now` and the health wait are unchanged and shared (*SPOT*; the restart script stays the single home of "how fused-memory restarts", and rebinding the socket is a restart that adopts the committed socket template). Idempotent: a second run on a converged host is a no-op install plus a restart plus a passing check. No separate `scripts/deploy/apply-loopback-binds.sh` exists — the earlier draft's wrapper collapsed into this mode.

## 4. Pre-conditions

None blocking. The FalkorDB recreate requires a current AOF, which `scripts/falkordb_aof_gate.py` proves or refuses at start; a refusal leaves `6379` on `0.0.0.0`, the exposure check fails, and γ escalates with the gate's own remedy lines in its stdout tail (`OPERATIONS.md` §"FalkorDB settings and the recreate gate").

## 5. Resolved design decisions

1. **Bind `:8002` and `:8003` to `127.0.0.1`; no auth layer, no tailnet bind.** Rejected: binding to the tailnet address `100.107.28.56` — exposes an unauthenticated task store and memory to every device and every process on the tailnet with no consumer to justify it, and needs `FreeBind=` ordering against `tailscale0`. Rejected: a bearer header checked in an ASGI wrapper (`main.py::_ASGIExceptionShield` is the seam) — a header is not a hard boundary for a server that stays on `0.0.0.0`, it needs a client change in twenty yamls plus `.mcp.json`, and credential delivery is non-trivial because `shared/src/shared/secret_env.py::agent_subprocess_env` strips `*_TOKEN` from agent environments. Loopback is the smallest change that is a hard boundary.
2. **Docker: loopback publish (`127.0.0.1:6379:6379`, `127.0.0.1:6333:6333`, `127.0.0.1:6334:6334`).** Rejected: `requirepass` / `QDRANT__SERVICE__API_KEY` — needs a secret in `fused-memory/.env`, in the compose healthchecks (`redis-cli ping`), in `scripts/falkordb_aof_gate.py`'s `INFO` reads and in every forensic script, and still leaves the ports on every interface. Rejected: a compose-internal network with no `ports` — fused-memory runs on the host (`fused-memory.service`), not in compose, so it needs a published port. A host-prefixed publish also drops the `[::]` mapping (verified by γ's check; §12 Open question 5 covers the fallback if it does not).
3. **One restart applies everything.** The `server.host` flip re-binds `:8003` and keeps `test_socket_listens_on_the_configured_endpoints` green only together with the template change; the compose change rides the `ExecStartPre` AOF-gated recreate. Rejected: separate deploys per endpoint — three closed-port windows instead of one.
4. **Apply through the committed restart script's new `--rebind-socket` mode, run as a deterministic auto-deploy** (`before_done` kind `deploy`, `script: scripts/restart-fused-memory.sh`, `args: ["--rebind-socket"]`, `target_unit: fused-memory.service`; precedent 2179/2212/2270 ran the same script), so the done-provenance is machine-stamped. Rejected: an operator hand-run from the runbook — no provenance, and the operator is the scarce resource this PRD is meant not to need. Rejected: a new standalone `scripts/deploy/apply-loopback-binds.sh` wrapper (the authored draft) — duplicates the recon-busy gate's call shape (INV-5) and, decisively, cannot be named by γ's `before_done` until it exists on `main` (§13). Rejected: committing a stub of that wrapper first (the 1976/1956 "pre-1" precedent) — a second tracked file whose only job is to exist.
5. **The exposure check is behavioural (connect probes), from structured sources.** Rejected: parsing `ss -ltnp` text (*structured data instead of meaningful strings*; the watchdog's `ss` parser is a tolerated precedent, not a pattern to extend). Rejected: reading ufw/nft/iptables — root-only, and the docker chains make the host rules a misleading answer.
6. **`ServerConfig.host` default becomes `'127.0.0.1'`.** A fresh checkout with no `server.host` line is then loopback by default; `config-docker.yaml` keeps its explicit `0.0.0.0`. Rejected: leaving the default — a config-less start would re-expose `:8003`.
7. **Escalation MCPs, the recon queue, and the dashboard are not touched.** They are loopback, test-pinned, and `_discover_escalation_urls`'s `127.0.0.1` default keeps working. Rejected: adding `escalation.host` lines to project yamls — a value that equals the default is lock-step duplication.
8. **Part 2 (authenticated off-host access) is excluded, not contracted** — see §6. Rejected: a contract-only section — a contract with no filed consumer is prose that drifts, and the choice of mechanism (bearer vs tailnet identity vs mTLS, token over ssh stdin vs MCP `headers`) depends on the consumer's shape, which is exactly what the unfiled PRD decides.

## 6. Out of scope

- **Authenticated off-host access to any factory MCP (Part 2).** No remote consumer exists; the only planned ones are the "remote agent leg" the T3 study recommends (`report.md` §5 item 3: "a dark-factory PRD, not a T3 feature") and attended T3 threads on another host, neither of which has a PRD. Under G1 a token mint, a header-delivery path and a tailnet bind with no named consumer are orphan producers, so none is specified here. What this PRD does establish for that future PRD, as facts not mechanisms: (a) after this PRD every factory endpoint is loopback, so off-host reach is a deliberate re-open, never an accident; (b) an agent cannot receive a credential through its environment — `shared/src/shared/secret_env.py::agent_subprocess_env` strips `*_TOKEN`/`*_API_KEY` and keeps only `CLAUDE_CODE_OAUTH_TOKEN` — so delivery must go through the MCP config `headers` block, for which `McpLifecycle.mcp_config_json(escalation_headers=…)` is the existing seam (it covers the escalation block only; fused-memory's block has no headers today); (c) the servers that a remote agent would need are fused-memory `:8002` and the project's escalation MCP, both of which already read `get_http_headers()` (escalation) or have an ASGI wrapper seam (`_ASGIExceptionShield`) where a check would sit; (d) a bind on the tailnet address only, never `0.0.0.0`; (e) `scripts/check_network_exposure.py`'s expected-reach table is where that PRD declares the exception. The study's §5 item 4 names this PRD's Part 1 as the prerequisite; it is met here.
- **Uid-level isolation of local untrusted consumers** (any local Unix account can call `submit_task`): owned by the client-portal deploy (scoping-intake task π / 183, memory `0a82f57d`), ruled 2026-10-23.
- **The dashboard's unauthenticated POST routes** and its launch path (`:8080` runs without a user unit; SB "Not found"). Loopback already; not a network exposure.
- **`scripts/orchestrator-watchdog.py::WATCHED` omits 8109 (scoping-intake) and 8110 (stream-touch)**, so `tests/scripts/test_orchestrator_socket_units.py` does not pin those two socket units. Noticed, not a network exposure (both are live `127.0.0.1`); the exposure check's live enumeration covers them. Not filed here.
- **`sccache-redis` published on `100.107.28.56:6380`** — a deliberate tailnet publish for the laptop's sccache (SB table), not dark-factory's.
- **T3 Code's bind** (`T3CODE_LAN`), already `127.0.0.1:3773` behind Tailscale Serve; owned by the T3 setup memory, not this repo.
- **Firewall rules.** Not readable without sudo; this PRD makes the host rules irrelevant to the factory's ports by not listening where they would apply.

## 8. Rollout order, disruption, rollback

**Order.** α lands (check only; no behaviour change). β lands: from that moment the committed template, `config.yaml` and compose differ from the installed socket unit and the live containers; a `systemctl restart fused-memory` in between does **not** rebind the socket (the service keeps the old listener) but **does** recreate the containers through the AOF gate, so the docker half may flip at the first fused-memory restart after β (a watchdog revive or `fm-staleness-redeploy`) before γ runs — harmless, every store consumer is loopback. γ dispatches once β is merged and runs the apply script.

**Disruption, stated for the operator and the watchers.** `:8002` and `:8103` are closed for one stop/start, 41–63 s measured; every open Claude session's fused-memory tools may be withdrawn until a manual `/mcp` (`OPERATIONS.md` §"Socket activation", Troubleshooting row "Every open Claude session's fused-memory MCP calls fail at once"). The in-flight reconciliation cycle is deferred by the recon-busy gate (cap 35 min) rather than cut. Orchestrators and the dashboard reconnect as they do for today's ~9 restarts a day. The merge lane notices only as it notices any fused-memory restart. `--rebind-socket` refuses to start while the transient `fm-staleness-redeploy.service` (`systemd-run` unit, §3) is active, so the two cannot interleave.

**Rollback.** The old unit is the previous template, byte-for-byte (`ListenStream=0.0.0.0:8002`). Revert β's commit on `main` except the `--rebind-socket` mode itself and re-run `scripts/restart-fused-memory.sh --rebind-socket` (it installs whatever template `main` carries, and the AOF-gated recreate restores the compose publish; the exposure check then reports the re-exposure, which is the expected red of a deliberate rollback). By hand: edit `~/.config/systemd/user/fused-memory.socket` back, `systemctl --user daemon-reload`, `systemctl --user stop fused-memory`, `systemctl --user start fused-memory.socket fused-memory`; for the containers, revert compose and restart fused-memory. `mcp__fused-memory__reload_config` and `mcp__escalation__reload_config` cover none of this (red tier / not in `RELOADABLE_FIELDS`).

## 12. Open (tactical) questions

1. **`[::1]:8002` as a second `ListenStream`?** Not needed on this host (`getent ahosts localhost` → `127.0.0.1` only). The implementer of β re-runs that probe at deploy time; if a host ever resolves `localhost` to `::1` first, add the line and widen the parity test, not the consumers.
2. **Cadence of the exposure check after γ.** Default: install-time (`setup-host.sh` §11) and deploy-time only. A `scripts/orchestrator-watchdog.py --report` line or a recurring predicate (`docs/task-authoring.md` §6.1) is a follow-up only if a regression is ever seen; the bind has no known drift source besides a template edit.
3. **`before_done.timeout_secs` 2700 vs `--now`.** Default keeps the recon-busy gate (a cycle is 9–30 min). If the operator prefers a bounded window, γ's `args` become `["--rebind-socket", "--now"]`; β decides whether the two flags compose or `--rebind-socket` takes `--now` as a modifier.
4. **`main.py` `display_host`:** the `'localhost' if host == '0.0.0.0'` special case becomes dead; β may delete it or leave it. Either is coherent.
5. **Docker IPv6 publish.** A `127.0.0.1:` host prefix is expected to drop the `[::]` mapping under docker 29.1.3 / compose 5.1.2; γ's check proves it. If a `[::]` row survives, the fallback is an explicit `"[::1]:6379:6379"` sibling mapping, not a daemon-level ip6tables change.
6. **`orchestrator/tests/_mcp_url_scan.py`.** The new scripts carry `127.0.0.1:<port>` literals for probes; if the URL sweep flags them, use its `mcp-url-sweep: allow` marker with the reason, as `main.py` and `stages/base.py` do.
